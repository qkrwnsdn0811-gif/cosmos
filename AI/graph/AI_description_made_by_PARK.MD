## [2] 기업 추출 — 사전과 NER

### 2-1. 사전 `dict-v1.3` (현재 운영 중)

| | |
| --- | --- |
| 종목 | **202개** (KOSPI 100 + NASDAQ 102) |
| 별칭 | **1,649개** — `삼성전자`, `삼전`, `Samsung Elec` … |

사전은 표기를 찾는 **동시에 티커를 준다**. 정확하지만 등록된 표기만 찾는다.
결과에는 매칭 방식과 신뢰도가 같이 붙는다. 뒤에서 거를 때 쓴다.

| `confidence` | `method` | 뜻 |
| ---: | --- | --- |
| 1.0 | `dict` | 사전 정확일치 — 가장 안전 |
| 0.9 | `ticker` | 문맥에 티커가 같이 있음 |
| 0.5 | `rule` | 그룹명을 지주사로 귀속 — **오탐이 여기 몰린다** |

> `"수주 규모는 한화로 3조원"` → 한화(000880) 로 잡힌다. `confidence 0.5`.

### 2-2. NER `ner-company-v2` (구현 완료, 운영 미연결)

사전에 없는 **새 표기**를 찾으려고 만들었다.

| | |
| --- | --- |
| 기반 모델 | `klue/roberta-base` |
| 라벨 | `O` / `B-COMPANY` / `I-COMPANY` |
| 학습 | 1 epoch · batch 16 · lr 3e-5 · max_len 128 · fp16 |
| 장비 | 로컬 RTX 4050 (6GB) |
| 데이터 | train 194,299 / dev 13,611 / test 8,070 |
| test F1 | **0.9874** |

**v1 의 실패가 v2 를 만든 이유다.** v1 은 사전이 만든 라벨(distant supervision)로만
학습했더니 **사전과 98.6% 겹치는 결과**를 냈다. 사전 밖 기업은 전부 `O` 로 배웠기
때문에, 새 표기를 찾으라고 만든 모델이 사전을 그대로 흉내내고 있었다.

v2 는 **KLUE-NER 의 사람이 붙인 기관명(OG) 라벨을 섞었다.** "조직 이름이란
무엇인가"를 따로 배우게 해서 포스코·현대제철·Micron 같은 미등록 표기도 잡게 했다.

```
distant positives 전량
distant negatives  positives 의 10% 까지만
KLUE train x3      OG 스팬 -> COMPANY, OG 없는 문장은 정답 negative
```

> ⚠️ **F1 0.9874 를 그대로 인용하면 안 된다.** 학습 라벨의 상당 부분이 사전에서
> 나왔으므로 이 숫자는 "사전을 얼마나 잘 재현하는가"에 가깝다. 추출 정확도가 아니다.

**링커** — NER 은 위치만 준다("34~38번째 글자가 기업명"). 그 표기를 종목코드로
바꾸는 것이 링커다(`삼전 → 005930`). 실패하면 `unresolved` 로 남긴다.

현재 운영 경로는 **사전만** 쓴다 (`model_name: dictionary-matcher`).
NER·링커는 `pipeline.py` 에 연결돼 있으나 아직 전환하지 않았다.

### 2-3. 산출 — 본문은 복사하지 않는다

| 테이블 | 단위 | 컬럼 |
| --- | --- | --- |
| `spans/` | 멘션 1건 | `record_id` `ticker` `alias` **`start` `end`** `method` `confidence` |
| `data/` | (기사, 기업) 쌍 | `record_id` `ticker` `n_mentions` `first_pos` `confidence` `method` `aliases` |

`start`/`end` 는 **`title + "\n" + body` 안의 문자 위치**다. 본문은 스냅샷에 그대로
두고 위치만 기록한다 — 복사하면 22.5GB 가 또 생기고 원본과 어긋날 수 있다.

`first_pos` 는 처음 등장한 자리다: `title` / `lead`(앞 200자) / `body`.

**실측 (사람 검수 192건)**

| 제목에 기업명 | 표본 | 사람이 채택 |
| --- | ---: | ---: |
| 있음 | 72 | **87.5%** |
| 없음 | 120 | 67.5% |

## [3] 선별 — 쓸 쌍만 남긴다

같은 기사라도 **이름만 스쳐 지나간 기업**은 빼야 한다. 안 그러면 시황표 한 장이
40개 종목의 "관련 기사"가 된다.

### 이전: B 분류기 (교사-학생)

로컬 LLM(Qwen)이 소량을 `include`/`review`/`exclude` 로 라벨링하고, 그 판단을
작은 모델(`MiniLM-L12`, 3분류)이 흉내내도록 학습시켜 전수 처리했다.

| | |
| --- | --- |
| 학습 데이터 | train **1,533쌍** / dev 256쌍 |
| 처리 | 2,514,445쌍 (전체 2,656,806의 94.6%) |
| 결과 | include 26.5% · needs_review 41.8% · exclude 31.7% |
| 비용 | 노트북 2대 × 수일 |

### 현재: 규칙으로 대체

B 가 통과시킨 쌍의 **63%를 뒤이은 근거 검사가 다시 걸렀다.** 실제로 일하고 있던
것은 분류기가 아니라 근거 검사였다. 그래서 분류기를 빼고 규칙을 쓴다.

```
버린다 = confidence < 1.0                              이름 충돌 ("한화로", "GS 인증")
      or 기사 내 기업 수 >= 10                          시황·나열
      or (n_mentions <= 1 and first_pos != "title")     스쳐 지나감
```

**실측 (사람 검수 192건 기준 정밀도)**

| | 정밀도 | 유지 비용 |
| --- | ---: | --- |
| B 분류기 | 75.0% | 470MB 모델 · 학습 1,533건 · 노트북 2대 |
| **규칙** | **93.3%** | 코드 3줄 |

> ⚠️ 이 표본은 **B 가 include 한 것만** 모았다. 잰 것은 정밀도뿐이고 **재현율은
> 측정하지 않았다.**

## [5] 근거 문장 추출

**모델 없음. 위치 계산만 한다.**

```
spans 의 start/end   →   그 위치가 몇 번째 문장인지   →   그 문장을 통째로 저장
```

산출은 `sentence_text`(문장 원문)와 `sentence_order`(순번). 화면에 뜨는
"근거 문장"이 이것이다.

> ⚠️ **오프셋 기준은 `title + "\n" + body` 다.** 본문만으로 문장을 자르면 제목
> 길이만큼 전부 밀려서 엉뚱한 문장이 근거로 붙는다.

근거 문장이 하나도 안 나온 쌍은 여기서 탈락한다. 실측으로 B-include 666,282쌍 중
**246,264쌍(37%)만** 통과했다.

## [6] 감성 분석 — FinBERT 2종

근거 문장 단위로 긍정/부정/중립을 매긴다. **기사 전체가 아니라 그 기업이 등장한
문장**에 대해서만 판단한다.

| 언어 | 모델 | 리비전 |
| --- | --- | --- |
| 한국어 | `snunlp/KR-FinBert-SC` | `f8586286cc3161fb648e9fee09a456069fd846d0` |
| 영어 | `ProsusAI/finbert` | `4556d13015211d73dccd3fdd39d39232506f3e43` |

문장에 한글이 있으면 한국어 모델, 없으면 영어 모델로 보낸다.

### 6-1. 라벨 순서가 반대다 — 가장 중요한 함정

| 모델 | 0 | 1 | 2 |
| --- | --- | --- | --- |
| `KR-FinBert-SC` | 부정 | 중립 | 긍정 |
| `ProsusAI/finbert` | **긍정** | 부정 | 중립 |

`argmax` 를 그대로 쓰면 **영어 쪽이 통째로 뒤집힌다.** 호재 기사가 악재가 된다.

반드시 모델 폴더의 `config.json` 에 있는 `id2label` 을 읽어서 매핑한다.
검증 함수가 이미 있다 — `lake_sentiment.py` 의 `label_indexes()` 가 세 클래스인지,
`label2id` 와 `id2label` 이 일치하는지 확인하고 아니면 예외를 던진다.

**리비전 고정 필수.** 허깅페이스에서 같은 이름으로 모델이 갱신되면 라벨 순서가
또 바뀔 수 있다.

### 6-2. 귀속 가드 — 문장이 정말 그 기업 이야기인지

직접 만들었다가 통과율이 **2.5%** 까지 떨어졌다. 공백을 지우는 바람에 `삼성` 이
`삼성전자` 안에서 매칭됐다. 기존 함수를 쓰면 **92.6%** 다.

```python
from kg_target_sentiment import _surface   # 문장부호 안 지움, 영문 경계만 확인
```

- 문장에 대상 기업명이 없으면 버린다
- **같은 기사에 붙은 다른 기업**이 그 문장에 있으면 버린다 (전체 유니버스가 아니다)
- 한 기업에 대해 문장마다 라벨이 갈리면 **NULL**. 다수결로 밀지 않는다

### 6-3. 장비

| | 속도 | 182,926건 기준 |
| --- | ---: | --- |
| CPU | 11 문장/초 | 며칠 |
| **GPU (RTX 4050)** | **184 문장/초** | **15분** |

**17배 차이**다. 서버에는 GPU 가 없으므로 근거 문장만 내려받아 로컬 GPU 에서 돌린다.
내려받는 것은 문장 텍스트뿐이라 원문 22.5GB 를 옮기지 않는다.

산출 → `company_document.sentiment` (실측 **212,673건**)
