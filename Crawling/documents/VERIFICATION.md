# 문서 Loader 구현 검증 기록

초기 구현 검증일: 2026-09-16 (KST). 아래는 운영 반영 전 격리 검증 기록이다.

이후 수행한 실제 운영 DB 적용·적재·자동 실행 연결은 [운영 반영 기록](../../deploy/document-loader/OPERATIONS.md)을 참고한다.

## 결과

국내 뉴스·해외 뉴스·DART·SEC 입력 어댑터와 PostgreSQL 문서 적재기를 검증했다. 운영 HDFS는 읽기만 수행했으며, SQL 실행과 Flyway 적용은 새로 시작한 격리 PostgreSQL에서 수행했다. 운영 DB의 V6 적용·실데이터 적재·자동 실행 서비스 배포는 수행하지 않았다.

| 검증 | 결과 |
|---|---|
| Python 테스트 | 98개 실행, 97개 통과, Windows 심볼릭 링크 생성 권한으로 1개 생략 |
| 실제 HDFS 입력 | 완료된 4개 입력, 총 19건 읽기·정규화 성공 |
| 실제 데이터 PostgreSQL 적재 | 뉴스 15건, 공시 4건, 기업 연결 21건 |
| 기본 dry-run | 실제 SQL 실행 후 출처·문서·연결·체크포인트 전체 롤백 |
| 동일 입력 재실행 | 추가 문서·연결 없음, 기존 행과 타임스탬프 불변 |
| CLI 실행 | 로컬 미러의 validate·dry-run·이미 적재한 배치 재실행 성공 |
| 런타임 최소 권한 | 운영 문서의 컬럼 단위 잠금 권한을 포함한 비관리자 역할로 성공 |
| Flyway | 신규 스키마 V1→V6, 기존 데이터가 있는 V5→V6, validate·재실행 성공 |
| 기존 마이그레이션 | V1–V5 내용과 Flyway 체크섬 불변 |
| 기존 DART 호환 | 데이터·문서 ID 유지, 최근 수집 시각 초기화, 기존 INSERT 구문 성공 |
| Linux 실행 스크립트 | Bash 구문 검사 성공 |

## 실제 데이터 확인 방법

Hadoop Master에서 현재 Loader의 HDFS reader로 실제 입력을 읽었다. 같은 입력의 로컬 미러와 정규화 결과·소비한 메타데이터 해시를 비교했다. 이 정규화 결과를 격리 PostgreSQL에 적재하고 제목·출처·URL·날짜·해시·HDFS 경로·공시 식별자·기업 연결을 전부 비교했다.

| 출처 | 실제 표본 수 | PostgreSQL 결과 |
|---|---:|---|
| 국내 뉴스 | 14 | `news_article` 14건 |
| 해외 뉴스 | 1 | `news_article` 1건 |
| DART | 3 | `disclosure` 3건, `filing_system=DART` |
| SEC | 1 | `disclosure` 1건, `filing_system=SEC` |

테스트 DB에는 프로젝트 기준정보의 해당 기업 14개만 준비했다. 출처는 5개, 적재 체크포인트는 4개가 생성됐다. 본문을 DB에 복제하거나 요약·감성·관계 점수를 생성하지 않았다.

## 주요 회귀 검증

- 같은 SEC accession을 서로 다른 CIK가 공유해도 별개의 공시로 적재한다. 실제 과거 SEC 데이터에서 확인된 형태를 재현했다.
- 동일 뉴스의 여러 기업 언급은 문서 하나와 여러 기업 연결로 저장한다. 검색 조건만 있는 ticker는 언급으로 취급하지 않는다.
- 동시 실행, 불일치한 체크포인트, 잘못된 회사·출처, 적재 후반의 DB 오류를 검증했다. 오류가 나면 해당 배치 전체를 롤백한다.
- 오래된 입력이 새 문서 내용을 덮어쓰지 않는다. 오래된 다른 본문의 기업 연결도 추가하지 않는다.
- 새 본문으로 기존 뉴스·분석 결과를 임의 교체하지 않는다. 명시적인 수정·재분석 절차가 필요한 경우 실패하며 기존 문서·기업 연결을 보존한다.
- 불완전한 입력, 해시·건수·식별자 불일치, staging 경로, 경로 탈출, 실제 HDFS 출처 경로 덮어쓰기를 거부한다.

## 환경 및 재현

Python 3.12, 격리 PostgreSQL 17.10, 애플리케이션의 Flyway 12.4.0 라이브러리를 사용했다. PostgreSQL 테스트는 실행마다 고유 스키마를 만들고 정리한다.

```bash
cd Crawling/documents
# TEST_DATABASE_URL에는 운영 DB가 아닌 격리 테스트 DB를 지정한다.
python -m unittest discover -s tests -p 'test_*.py' -v
```

`TEST_DATABASE_URL`이 없으면 PostgreSQL 통합 테스트가 생략된다. SQL 직접 실행 테스트와 실제 Flyway 검증은 서로 별도로 수행했다. 설치·입력 검증·적재 방법은 [README](README.md), 운영 계정 권한과 실행 설정은 [배포 문서](../../deploy/document-loader/README.md)를 참고한다.

이 표본 검증은 모든 과거 데이터의 운영 전량 적재나 성능 검증을 의미하지 않는다. 새 입력의 자동 탐색·주기 실행은 운영 연결이 필요하며, 기업 매칭이 없는 뉴스는 이후 NER 단계에서 기업 연결을 보완해야 한다.
