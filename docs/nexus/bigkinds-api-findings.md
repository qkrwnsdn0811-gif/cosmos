# 빅카인즈 API 실측 결과 (0단계)

- 측정: 2026-10-13 23시경 (KST), 호출 25회, 호출 간 1초 간격
- 방법: 일회용 실측 스크립트. 응답 원본은 기사 내용이 들어 있어 저장소에 넣지 않았다.
- 기준 문서: 「빅카인즈 OpenAPI 사용자 지침서 newstore_V1.0」

## 1. 결론

1. 본문(`content`)은 검색과 상세 조회(`news_ids`) 모두 **200자**다. 전체 본문은 받을 수 없다.
2. 지침서에 없는 **개체명 필드 4개가 실제로 반환된다**: `tms_ne_organization`, `tms_ne_person`, `tms_ne_location`, `tms_ne_stream`. 전체 본문 기준이며, `tms_ne_stream`은 문장 단위로 보이는 구간별 개체 목록이다. 기업 인식과 같은 문장 동시언급을 본문 없이 할 수 있다.
3. 수집량이 예상보다 크다. `경제>반도체`만 연 14만~19만 건, `경제>자동차`는 연 32만~35만 건이다.
4. `"A AND B"` 검색의 `hilight`는 두 기업명을 모두 포함한 구간을 준다 (5건 중 5건).
5. `/feature`, `/keyword`는 60초 후 504 오류로 응답하지 않았다. 설계에서 의존하지 않는다.
6. 25회 연속 호출에서 호출 제한은 나타나지 않았다.

## 3. 기사 필드

문서에 있는 필드는 모두 반환된다: `news_id`, `title`, `content`, `published_at`, `enveloped_at`, `dateline`, `provider`, `category`, `category_incident`, `byline`, `provider_link_page`, `printing_page`, `tms_raw_stream`, `provider_news_id`, `publisher_code`, `images`, `images_caption`, `provider_subject`, `subject_info`.

| 필드 | 형식 | 쓰임 |
|---|---|---|
| `content` | 본문 앞 200자 | 화면 미리보기 |
| `published_at` | 날짜만 (`T00:00:00+09:00`) | 기사 날짜 |
| `dateline` | 실제 출고 시각 (예: `23:14:42`) | 초과수익률 기준 시각 |
| `tms_raw_stream` | 전체 본문의 명사구를 `\n`으로 구분, **본문 순서대로** (예시 기사 173개) | 관계 단서 단어(공급·납품·경쟁 등)의 위치 피처 |
| `tms_ne_organization` | 기관명을 `\n`으로 구분 | 기업 언급 인식 (사전 매칭) |
| `tms_ne_person` / `tms_ne_location` | 인물·장소를 `\n`으로 구분 | 보조 |
| `tms_ne_stream` | 구간은 `\n`, 구간 안의 개체는 `,`, 개체는 `이름:유형` | 같은 문장 동시언급 |
| `provider_link_page` | 원문 URL (없는 기사도 있음) | 근거 링크. **접속하지 않는다** |

`tms_ne_stream`의 개체 유형: `OG`(기관), `PS`(인물), `LC`(장소), `DT`(날짜), `QT`(수량), `PR`(상품·기타), `OC`(직위), `EV`(행사), `PS_CLUE`(인물과 소속, 예: `인물#회사 회장:PS_CLUE`).

예시 기사 3건의 구간 수는 38, 21, 12였다. 같은 구간에 함께 나온 기관 쌍은 각각 10, 3, 14쌍이었다.

주의할 점:

- 기관 목록에 약칭이 섞인다 (예: `SK하닉`, `삼전닉스`). 별칭 사전에 넣어야 한다.
- 국가와 정부 기관도 `OG`로 잡힌다 (예: `중국`, `정부`, `국회`). 기업 사전과 매칭되는 것만 쓴다.
- 구간 경계가 정확히 문장 단위인지는 표본 3건으로만 확인했다.

## 4. `/changeTracker/news` 동작

- `from=2026-10-13 12:00:00`, `interval=MIN_15`로 요청하자 `update_dt`가 11:45:29부터 호출 시점(23:15)까지인 1,669건이 왔다. **`from`에서 `interval`만큼 거슬러 올라간 시점부터 현재까지**를 주는 것으로 보인다.
- 상태값은 `Update` 1,662건, `Cancelled` 7건이다. `Insert`는 나오지 않았다. 신규 기사도 `Update`로 오는 것으로 보인다.
- `pub_date` 분포: 당일 1,426건, 전날 100건, 다음 날 42건, 그 이전 소수.
- **취소(`Cancelled`) 기사는 서비스에서 내려야 한다.**
- 11시간 반에 1,669건이므로 실시간 수집 부하는 작다. 15분마다 변경이력 1회 + 상세 조회(100건 단위)로 충분하다.

## 6. 설계 반영 사항

1. **기업 인식:** `tms_ne_organization`을 기업 사전과 매칭하는 것을 기본으로 한다. KPF-NER은 제목과 hilight처럼 텍스트가 있는 곳의 보조로 낮춘다.
2. **같은 문장 동시언급:** `tms_ne_stream`으로 구한다. 기사 단위보다 강한 관계 후보 신호이고, 동시언급 PMI도 문장 단위로 계산할 수 있다.
3. **관계 유형 판별 입력:** `"A AND B"` hilight 구간(텍스트)과 `tms_raw_stream`의 단서 단어 위치(피처)를 함께 쓴다.
4. **수집 범위:** 분류 전체를 3년치 받으면 약 180만 건이다. 1단계는 `경제>반도체` 2025-01부터 현재까지(약 35만 건, 10,000건 단위 약 40회 호출)로 시작하고, 기업 사전에 매칭되는 기사만 분석 대상으로 삼는다. 자동차 분류는 기업과 무관한 기사가 많을 가능성이 커서 기업명 검색 위주로 수집한다.
5. **실시간:** 기획서대로 `/changeTracker/news` 15분 주기 + `news_ids` 상세 조회로 간다. 취소 기사 처리를 넣는다.
6. **`/feature`, `/keyword`:** 쓰지 않는다. 기사별 키워드는 `tms_raw_stream`과 `tms_ne_*`로 대신한다.

## 7. 아직 확인하지 않은 것

- `news_ids` 한 번에 넣을 수 있는 최대 개수 (100개는 가능)
- 10,000건 단일 요청의 응답 시간과 크기
- 장시간 대량 호출 시 제한 여부 (본 수집 중에 관찰)
- `/feature`, `/keyword` 재시도
