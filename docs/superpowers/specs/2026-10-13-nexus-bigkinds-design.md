# NEXUS 본선 설계: COSMOS 위에 빅카인즈 API 적용

- 작성일: 2026-10-13
- 대상: 2026 뉴스빅데이터 해커톤 본선 (일반 부문, 「넥서스(NEXUS) — 뉴스 기반 공급망 리스크 인텔리전스」)
- 기준 코드: COSMOS (`main` 브랜치, 해커톤 작업 전 상태)

## 1. 목표와 성공 기준

**목표.** 예선 기획서 「넥서스」를 본선 개발 기간(2026-10-12 ~ 10-30) 안에 동작하는 프로토타입으로 만든다. 뉴스 소스는 전량 빅카인즈 API로 교체하고, 기사에 언급된 기업(근거, reported)과 언급되지 않았지만 공급망으로 이어진 기업(추정, inferred)을 분리해 보여준다.

**성공 기준 (10/30 코드 동결 시점).**

1. 반도체·2차전지·자동차 3개 밸류체인을 대상으로 다음 흐름이 실제 데이터로 동작한다.
   빅카인즈 기사 1건 선택 → 근거(실선)·추정(점선) 관계 지도 → 기업별 뉴스 전후 초과수익률 → 근거 패널(언론사·날짜·원문 링크)
2. 신뢰도가 기준 미만인 기업은 '판단 보류'와 사유를 표시한다.
3. 실시간 수집(15분 주기)이 동작하고, 관심 기업이 추정 영향권에 들어오면 알림이 뜬다.
4. 시연 영상, 화면 캡처, 설명자료, 기존·신규 구분표가 준비되어 있다. 공개 PT 심사는 11/3이다.

## 2. 제약과 결정 사항

| 항목 | 결정 | 근거 |
|---|---|---|
| 인프라 | 단일 서버 경량 구성. Hadoop·Kafka·Spark를 쓰지 않는다 | SSAFY 서버 종료. 3개 밸류체인 규모는 단일 머신으로 충분 |
| 인원 | 개발자 2~3명, 트랙 2개 (A: 데이터·AI, B: 서비스) | 사용자 답변 |
| 뉴스 수집 | 빅카인즈 API만 사용. COSMOS 크롤러와 네이버·야후 수집기는 실행하지 않는다 | 대회 요강: 본선 API 필수, 크롤링 금지 |
| AI 모델 | 서비스 경로는 KPF-BERT 계열만 사용. 로컬 LLM(GPU PC)은 학습용 초벌 라벨 생성에만 사용 | 상용 LLM 키 없음. 재단 모델 활용. 수치 판단은 학습 모델이 맡는다는 기획서 원칙과 일치 |
| 개발 순서 | 반도체 하나로 전체 흐름을 먼저 연결한 뒤 부품을 업그레이드 (접근 A) | 언제든 시연 가능한 상태를 유지 |
| 코드 분리 | 신규 코드는 `nexus/`(Python), 백엔드 `event` 도메인, 프론트 `features/event`에 둔다. 작업 전 상태에 git 태그 `pre-hackathon-baseline`을 붙이고 해커톤 작업은 `nexus` 브랜치에서 한다 | 요강: 기존 구현과 신규 개발 범위를 명확히 구분해야 함 |
| 본문 저장 | 기사 본문을 저장하지 않는다. 근거로는 검색어 주변 구간(hilight)과 원문 링크만 보관 | 기획서 정책. API도 본문을 200자만 제공 |

## 3. 빅카인즈 API 사실 (지침서 newstore_V1.0 + 2026-10-13 실측)

실측 상세는 [`docs/nexus/bigkinds-api-findings.md`](../../nexus/bigkinds-api-findings.md)에 있다.

| 사실 | 설계 영향 |
|---|---|
| `content`는 검색과 상세 조회(`news_ids`) 모두 200자다 (실측 확인) | COSMOS의 전체 본문 문장 단위 근거 추출을 쓸 수 없다. hilight 방식으로 간다 |
| 지침서에 없는 `tms_ne_organization`·`tms_ne_person`·`tms_ne_location`·`tms_ne_stream`이 반환된다 (실측) | 기업 인식은 `tms_ne_organization` × 기업 사전이 기본이다. 같은 문장 동시언급은 `tms_ne_stream`으로 구한다 |
| `tms_raw_stream`은 전체 본문의 명사구를 본문 순서대로 담는다 (실측) | 관계 단서 단어(공급·납품·경쟁 등)의 위치를 관계 판별 피처로 쓴다 |
| `hilight`는 검색어가 포함된 구간을 최대 200자로 준다 | `"A AND B"` 검색으로 두 기업이 함께 나오는 구간을 얻어 관계 근거로 쓴다 |
| `/changeTracker/news`는 기사 ID와 상태(`Update`, `Cancelled`)만 준다. `from`에서 `interval`만큼 거슬러 올라간 시점부터 현재까지를 반환한다. 11시간 반에 1,669건 (실측) | 실시간 수집은 ID 수집 → `news_ids` 상세 조회(100개 단위)의 2단계다. 취소 기사는 서비스에서 내린다 |
| `/feature`, `/keyword`는 504로 응답하지 않았다 (실측) | 의존하지 않는다 |
| 수집량: `경제>반도체` 연 14만~19만 건, `경제>자동차` 연 32만~35만 건, 2차전지 검색어 연 7만~10만 건 (실측) | 1단계는 `경제>반도체` 2025-01부터 현재까지로 시작한다. 자동차는 기업명 검색 위주로 수집한다 |
| `published_at`은 날짜만 담는다 (00:00 고정). `dateline`은 실제 출고 시각이다 | 초과수익률 라벨의 기준 시각은 `dateline`이다 |
| 통합 분류에 `경제>반도체`, `경제>자동차`가 있고 2차전지는 없다 | 반도체·자동차는 분류로, 2차전지는 검색어로 수집한다 |
| 사건/사고 분류는 범죄·사고·재해·사회 위주다. 리콜·수출규제·수주 같은 기업 이벤트는 없다 | 기업 이벤트 유형은 KPF-BERT 분류기로 직접 부여한다 |
| `return_from` 최대 20,000, `return_size` 최대 10,000 | 과거 기사는 기간을 잘게 나눠 수집한다 |
| 호출 한도가 지침서에 없다. 25회 연속 호출에서는 제한이 없었다 (실측) | 본 수집 중에 계속 관찰한다 |
| `/issue_ranking`은 하루 이슈 30개와 이슈별 재단 요약문(`topic_content`), 같은 사건 기사 ID 목록(`news_cluster`)을 준다 (실측) | 중복 기사 묶기와 이벤트 요약에 쓴다 |
| `"A AND B"` 검색의 hilight는 두 기업명을 모두 포함한다 (5건 중 5건, 실측) | 관계 판별기의 텍스트 입력으로 쓴다 |

## 4. 전체 구조

```text
[빅카인즈 API]  직렬 호출 클라이언트 (응답 원본은 디스크에 캐시)
  ├ 과거 기사: /search/news   경제>반도체·경제>자동차 분류 + 2차전지 검색어, 기간 분할 수집
  ├ 실시간:    /changeTracker/news 15분 주기 → news_ids 상세 조회
  └ 보강:      /issue_ranking(매일), /time_line·/word_cloud(기업별), "A AND B" hilight
        ↓
[원본 저장]  로컬 Parquet (raw → analyzed 단계 구분)
        ↓
[분석 — Python, GPU PC]
  ① 기업 인식    tms_ne_organization × 기업 사전 (AI/ner matcher 재사용), 같은 문장 동시언급은 tms_ne_stream
  ② 이벤트 유형  재단 분류 + KPF-BERT 이벤트 분류기
  ③ 근거 관계    두 기업 구간 → COSMOS 규칙 → KPF-BERT 관계 판별기로 교체
  ④ 기준 그래프  근거 관계 + DART 지분 관계 + 동시언급 PMI (+ 산업연관표, 여유 시)
  ⑤ 추정 전이    기준 그래프에서 최대 2단계 가중 전파, 경로 라벨, 신뢰도 미달 → 판단 보류
  ⑥ 영향 모델    초과수익률 3분류 라벨로 학습, 시계열 분할 검증
        ↓
[PostgreSQL]  기존 스키마 + V10 신규 테이블
        ↓
[Spring Boot] 신규 /api/events/* + 기존 그래프·기업 API
        ↓
[React]       이벤트 목록, 뉴스별 관계 지도(신규), 근거 패널, 알림
```

| 기업 마스터·사전 | `nexus/entities/` | 3개 밸류체인 코스피·코스닥 150~250개사, 별칭 사전, KPF-NER 후보 추출 | `AI/ner/matcher.py`, `AI/ner/data/companies.csv` 형식 |

### 4.2 신규 데이터 모델 (Flyway V10)

- `news_event`: 빅카인즈 `news_id`, `source_document` 참조, 통합 분류, 사건/사고 분류, 이벤트 유형과 신뢰도, `dateline`, 이슈 묶음 ID
- `event_company_impact`: 이벤트 × 기업. `basis`(reported / inferred), 단계 수(0 = 기사 언급), 전이 경로(관계 유형 목록), 영향 방향·크기·신뢰도, 상태(OK / HOLD)와 판단 보류 사유, 모델 버전
- `event_abnormal_return`: 이벤트 × 기업의 관측 초과수익률 (+1일, +3일), 비교 지수
- 기존 `company_relationship`은 기준 그래프로 재사용하고 관계 출처(뉴스 / DART / 산업연관표)를 구분하는 컬럼을 추가한다.

근거와 추정은 `basis` 컬럼으로 저장 단계에서부터 분리한다. 추정 행에는 근거 문서를 연결하지 않고, 전이 경로를 이루는 각 관계의 근거로만 거슬러 올라간다.

### 4.3 화면

- **뉴스별 관계 지도 (신규):** 기획서 [그림 1]처럼 중심에 이벤트, 안쪽 원에 근거 기업(실선), 바깥 원에 추정 기업(점선)을 둔다. 노드 색은 영향 방향, 크기는 영향 크기, 회색은 판단 보류다. 기존 `RelationMap2D.tsx`는 관계 유형별 목록이고 1홉 확장 기능이 제거된 상태라 새로 만든다. 허브 하나에 위성 여러 개인 구조에는 원형 배치가 맞다.
- **근거 패널:** 노드나 관계를 누르면 근거 구간, 언론사, 날짜, 원문 링크, 과거 유사 사례를 보여준다.
- **3D 은하:** 기존 화면을 유지하고 밸류체인 필터만 추가한다.
- **알림:** 관심 기업이 추정 영향권에 들어오면 앱 안에서 알린다. 근거 링크를 붙인다.

### 4.4 AI 역할 분리

| 기획서 역할 | 구현 | 비고 |
|---|---|---|
| 이벤트 구조 추출 | 재단 분류 + KPF-NER + KPF-BERT 이벤트 유형 분류기 | 자유 형식 추출 대신 정해진 유형 분류 |
| 관계 문장 판별 | hilight 구간을 KPF-BERT 분류기로 공급 / 경쟁 / 협력 / 단순 나열 판별 | 초벌 라벨: COSMOS 규칙 + 로컬 LLM, 사람이 검수 |
| 근거 요약 | 재단 요약문(`topic_content`) + 근거 구간 원문 + 원문 링크 | 생성 요약을 쓰지 않음 |
| 영향 방향·크기 | 초과수익률 라벨로 학습한 분류 모델 | 생성형 모델은 수치 판단에 관여하지 않음 |
| 간접 전이 | 규칙 기반 가중 전파 (1순위), GNN (2순위, 여유 시 비교) | |

사용할 KPF 모델: `KPF/KPF-bert-ner`(개체명 150종, 기업 유형 태그 OGG_ECONOMY. 빅카인즈가 기사별 개체명을 주므로 제목·hilight 보조와 사전 보강 후보 발굴에만 쓴다), `kpfbert`(분류기 파인튜닝 바탕), `kpfSBERT`(유사 사례, 가중치 미공개라 직접 학습하거나 대체 임베딩 사용). `KPF-BERTSum`은 전체 본문이 필요해 쓰지 않는다.

## 5. 단계별 개발 계획

트랙 A는 데이터·AI(수집, 사전, 관계, 전이, 모델), 트랙 B는 서비스(DB, API, 화면)다. 개발자가 3명이면 A를 A1(수집·그래프)과 A2(모델)로 나눈다. 개발자가 아닌 팀원은 밸류체인 매핑과 라벨 검수를 맡는다.

| 단계 | 기간 | 트랙 A | 트랙 B | 완료 기준 |
|---|---|---|---|---|
| 0. 준비·실측 | 10/13~14 | 기준 태그, 크롤러 끄기, `nexus/` 뼈대, 빅카인즈 전 엔드포인트 실측, 반도체 기업 마스터 초안 약 50개 | JDK 21 설치, Docker DB, 백엔드·프론트 로컬 실행, V10 스키마와 이벤트 지도 API 형식 확정 | 실측 결과 문서, 로컬에서 COSMOS 동작, 스키마·API 형식 합의 |

## 6. 검증

- **코드 테스트:** `nexus/` 모듈은 pytest로 테스트한다. 빅카인즈 클라이언트 테스트는 0단계에서 저장한 실제 응답 파일을 쓰고 API를 호출하지 않는다. 기존 백엔드 테스트(`gradlew test`)를 계속 통과시킨다.
- **분류기:** 검수 라벨 일부를 학습에서 제외해 정밀도·재현율·F1을 재고 COSMOS 규칙과 비교한다. 검수 목표는 관계 약 500건, 이벤트 약 300건이다. 규칙보다 낮으면 규칙을 유지한다.
- **영향 모델:** 시계열 분할로 검증한다 (예: 2025년 상반기까지 학습, 이후 검증). 기준선은 '항상 중립'과 '감성만 사용' 두 가지다. 기준 시각은 `dateline`이고 장 마감(15:30 KST) 후 기사는 다음 영업일로 처리한다.
- **전이 추론:** 정답 데이터가 없으므로 알려진 공급망 사건에서 추정 기업이 실제로 초과 반응을 보였는지 적중률을 재고 도메인 담당이 검수한다.
- **통합:** 데모 시나리오 3개를 처음부터 끝까지 확인하는 체크리스트로 만들어 각 단계가 끝날 때 다시 확인한다.
