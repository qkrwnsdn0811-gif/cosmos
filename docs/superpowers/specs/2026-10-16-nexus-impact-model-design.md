# NEXUS 2단계 설계: 영향 방향·크기 모델

- 작성일: 2026-10-16
- 범위: 전체 설계([2026-10-13-nexus-bigkinds-design.md](2026-10-13-nexus-bigkinds-design.md)) 2단계 중 **영향 모델**만 다룬다. KPF-BERT 관계 판별기, 이벤트 분류기, 실시간 수집은 이 문서에 넣지 않는다.
- 기준 데이터: 계획 1의 반도체 수집·분석 결과(`경제>반도체` 2025-01 ~ 2026-10-13, 이벤트 129,864건, [slice1-run.md](../../nexus/slice1-run.md) §5 조정 후)

## 1. 목표와 성공 기준

**목표.** 지도에 나온 국내 상장 기업마다 "이 기사 뒤에 주가가 시장보다 오를지, 내릴지, 그대로일지"를 과거 사례로 학습한 모델로 추정해 방향, 신뢰도, 세기로 보여준다. 확신이 부족하면 방향을 비워 둔다(방향 보류).

**성공 기준.**

1. `nexus sentiment` → `train-impact` → `predict-impact` 순으로 실행하면 `event_company_impact`의 `impact_direction`, `impact_magnitude`, `confidence`가 채워진다.
2. 검증 보고서 `docs/nexus/impact-model-report.md`가 생성되고, 시험 구간에서 전체 모델과 기준선 3개(항상 중립, 규칙, 감성만)를 같은 지표로 비교한다. 모델이 기준선보다 낫지 않아도 숫자를 그대로 싣는다.
3. 지도에서 상승, 하락, 중립, 방향 보류가 구분되어 보이고, 근거 패널에 방향, 신뢰도, 세기와 고지 문구가 나온다.
4. 모든 단계에 자동 테스트가 있고, 기존 테스트(파이썬, 백엔드 211개, 프론트 12개)가 계속 통과한다.

## 2. 결정 사항

| 항목 | 결정 | 근거 |
|---|---|---|
| 모델 | scikit-learn `HistGradientBoostingClassifier` 3분류 | CPU에서 몇 분 만에 학습. "감성 × 관계 종류" 같은 상호작용을 직접 학습한다(경쟁사의 악재가 호재일 수 있음) |
| 비교 기준선 | 항상 중립, 규칙(감성 × 경로 부호), 감성만 | 기획서의 "학습 모델" 요구를 충족하면서 모델이 실제로 더하는 몫을 보여준다 |
| 감성 모델 | `snunlp/KR-FinBert-SC`, 리비전 `f8586286cc3161fb648e9fee09a456069fd846d0` | COSMOS(`AI/gpu_news/download_models.py`)와 같은 고정 버전. 라벨 순서 0=부정, 1=중립, 2=긍정 |
| 실행 장치 | CPU (Ryzen 7 7800X3D) | 이 PC 그래픽카드는 AMD RX 9070 XT라 CUDA가 없다. 감성 분석 1회 약 1시간이면 감당 가능 |
| 정답 기준 | 평소 변동폭 대비 1일 초과수익률 (아래 §3.2) | 종목마다 변동성이 달라 고정 % 기준은 소형주에 치우친다 |
| 방향 보류 표시 | 속이 빈 원 | 관계 판단 보류(회색)와 방향 보류를 눈으로 구분한다 |
| 스키마 | 바꾸지 않는다 | V10에 세 컬럼이 이미 있다. V10 파일은 수정 금지 |

## 3. 데이터와 정답

### 3.1 표본

- 단위: (이벤트, 기업) 쌍. `event_company_impact`에 해당하는 분석 결과(`events.pkl`의 `Impact`) 중 `status = OK`이고 시장이 KOSPI 또는 KOSDAQ인 것.
- 정답(§3.2)을 계산할 수 없는 쌍은 학습·평가에서 뺀다. 예측(§5.4)에서는 뺄 필요가 없다.
- 표본 가중치: 같은 기업·같은 거래일(`trading_date`)에 걸린 표본이 n개면 각각 1/n. 하루 기사 수백 건인 삼성전자·SK하이닉스가 학습을 덮지 않게 한다. 모든 지표도 이 가중치로 계산한다.
- 시계열 분할(이벤트 거래일 t0 기준):

  | 구간 | t0 |
  |---|---|
  | 학습 | ~ 2025-12-31 |
  | 검증 | 2026-01-01 ~ 2026-06-30 |
  | 시험 | 2026-07-01 ~ 정답을 계산할 수 있는 마지막 날 |

### 3.2 정답

- 일별 초과수익률 AR_d = (종가_d / 종가_d-1 − 1) − (지수 같은 계산). 지수는 기존과 같다(KOSPI 기업은 KOSPI, KOSDAQ 기업은 KOSDAQ).
- 평소 변동폭 σ = t0 전날까지 60거래일의 AR_d 표준편차. 60일 중 50일 이상 값이 있어야 한다. 없으면 정답 없음.
- z = (t0의 1일 초과수익률) / σ. 1일 초과수익률은 기존 `abnormal_returns(..., windows=(1,))`와 같은 정의다(t0 전날 종가 → t0 종가).
- z > 0.5 상승(`POSITIVE`), z < −0.5 하락(`NEGATIVE`), 그 사이 중립(`NEUTRAL`).
- 주가 조회 기간: 첫 이벤트 150일 전 ~ 오늘. 기존 `PriceCache`를 그대로 쓴다(디스크 캐시, 빠진 구간만 조회).

### 3.3 입력 특징

기업 ID와 종목코드는 넣지 않는다. 특정 종목을 외워 맞히는 것을 막기 위해서다. 모든 특징은 기사 출고 시각에 알 수 있는 정보만 쓴다.

| 묶음 | 특징 | 정의 |
|---|---|---|
| 기사 | 감성 확률 3개 | KR-FinBERT의 부정·중립·긍정 확률. 입력은 제목 + 본문 200자 |
| | 분류 | 학습 구간 기사의 1% 이상에 나오는 빅카인즈 분류를 여러 개 켤 수 있는 0/1 값으로 |
| | 사건/사고 여부 | `incidents`가 비어 있지 않으면 1 |
| | 활성 관계 종류 | `active_relations(article)`의 SUPPLY·PARTNER·COMPETE·INVEST 각각 0/1 |
| | 언급 기업 수 | 이벤트의 REPORTED 기업 수 |
| | 장 마감 후 여부 | 출고 시각이 15:30 KST 이후이거나 출고일이 거래일이 아니면 1 |
| 이벤트 속 기업 | basis, hop, 전파 점수 | `Impact.basis`, `hop`, `score` |
| | 언급 위치 | 제목·본문·개체명 목록 각각 0/1 (`CompanyMention.sources`). 추정 기업은 모두 0 |
| | 첫·마지막 관계 | 경로 첫 단계와 마지막 단계의 관계 종류. 경로가 없으면 `NONE` |
| | 경로 부호 | 단계별 부호의 곱. SUPPLY·PARTNER·INVEST는 +1, COMPETE는 −1, CO_MENTIONED는 0. 언급 기업은 +1 |
| | 간선 출처 | 경로 첫 단계의 출처(NEWS·COSMOS·COMENTION). 없으면 `NONE` |
| | 역할, 시장 | `Company.role`, `Company.market` |
| 기업 맥락 | 기사 수 급증 배율 | 출고 시각 직전 24시간 동안 그 기업을 언급한 기사 수 ÷ (직전 30일 하루 평균 + 1). 우리가 수집한 기사로 센다 |
| | 직전 5일 수익률 | t0 전날 종가 / 그보다 5거래일 앞 종가 − 1 |
| | 최근 변동성 | §3.2의 σ |

범주형 특징(관계 종류, 간선 출처, 역할, 시장)은 모델의 범주형 입력으로 넣는다. 값이 없으면 결측으로 두고 모델이 그대로 처리한다.

## 4. 모델

### 4.1 학습과 보정

- 고정 하이퍼파라미터로 학습한다(그리드 탐색 없음): `learning_rate=0.05`, `max_iter=500`, `early_stopping=True`, `validation_fraction=0.1`, `l2_regularization=1.0`, `random_state=0`.
- 학습한 모델을 고정한 채 검증 구간에서 확률을 보정한다(시그모이드, 클래스별 일대다 후 정규화). "신뢰도 60%"가 실제로 60% 안팎 맞게 하려는 것이다.
- 출력: **방향** = 세 확률 중 가장 큰 클래스, **신뢰도** = 그 확률, **세기** = |p_상승 − p_하락|. 세 값 모두 소수 여섯째 자리까지 저장한다.

### 4.2 방향 보류 기준 τ

- 후보: 0.40, 0.45, …, 0.90.
- 후보마다 검증 구간에서 신뢰도 ≥ τ인 표본만 모은다. 그 표본이 200건 이상이고, 그 표본에서 모델 정확도가 "항상 중립" 정확도보다 10%p 이상 높으면 통과다.
- 통과한 후보 중 가장 작은 값을 τ로 쓴다. 통과한 후보가 없으면 τ = 0.6으로 두고 보고서에 "기준 미달"로 적는다.
- 신뢰도 < τ이면 방향을 null로 저장한다. 신뢰도와 세기는 그대로 저장한다.

### 4.3 기준선

| 이름 | 방법 |
|---|---|
| 항상 중립 | 모든 표본을 중립으로 |
| 규칙 | 감성 분류(세 확률 중 최대)의 부호 × 경로 부호. 부호가 0이면 중립 |
| 감성만 | 같은 모델과 같은 보정 과정을 감성 확률 3개만 넣어 학습 |

## 5. 파이프라인

### 5.1 명령

| 명령 | 하는 일 | 결과 |
|---|---|---|
| `nexus sentiment --chain semis` | 이벤트 기사에 KR-FinBERT를 CPU로 돌린다. 같은 리비전으로 이미 점수를 낸 기사는 건너뛰고, 일정 배치마다 저장해 중단돼도 이어서 돌린다 | `nexus/data/analyzed/semis/sentiment.parquet` (news_id, p_neg, p_neu, p_pos, model_revision) |
| `nexus train-impact --chain semis` | 데이터셋을 만들고 학습, 보정, τ 선택, 기준선 포함 시험 평가를 한다 | 모델 파일 `nexus/data/models/impact-hgb-v1-semis.joblib`(git 제외, 특징 목록·범주 값·τ·분할 날짜 포함) + `docs/nexus/impact-model-report.md`(커밋) |
| `nexus predict-impact --chain semis --database-url …` | 대상 행 전체를 예측해 DB에 쓴다 | `event_company_impact`의 세 컬럼과 `model_version` 갱신 |

실행 순서는 `analyze` → `load` → `sentiment` → `train-impact` → `predict-impact`다. `load`는 이벤트마다 영향 행을 지우고 다시 넣으므로, `load`를 다시 돌리면 `predict-impact`도 다시 돌려야 한다.

### 5.2 코드 구성 (`nexus/nexus/impact/`)

| 모듈 | 책임 |
|---|---|
| `labels.py` | 일별 초과수익률, 60일 σ, z, 정답 |
| `sentiment.py` | KR-FinBERT 감싸기(배치, 캐시, 이어 돌리기). 모델 객체를 주입받아 테스트는 가짜 모델로 돌린다(torch 불필요) |
| `features.py` | 이벤트, 감성, 주가, 기사 수로 특징 표를 만든다. 학습과 예측이 같은 함수를 쓴다 |
| `model.py` | 학습, 보정, τ 선택, 기준선, 평가 지표, 예측, 모델 파일 저장·불러오기 |
| `report.py` | 평가 결과로 마크다운 보고서를 쓴다 |

`pipeline.py`에 세 명령을 추가하고, DB 갱신 함수는 `load/postgres.py`에 둔다.

### 5.3 의존성

- 기본 의존성에 `scikit-learn>=1.6`, `joblib`을 추가한다(보정에 `FrozenEstimator`를 쓴다).
- `torch`(CPU)와 `transformers`는 선택 의존성 `[ml]`에 둔다. `[ml]` 없이도 기존 테스트와 새 테스트가 모두 돈다.

### 5.4 예측과 DB 반영

- 대상: 해당 밸류체인의 `status = 'OK'`이고 KOSPI·KOSDAQ 기업인 행 전체(학습·검증·시험 구간 모두).
- 관계 판단 보류(HOLD) 행과 나스닥 기업 행은 세 컬럼을 null로 둔다. 관계 자체가 불확실하거나 주가 맥락 특징이 없기 때문이다.
- 한 트랜잭션 안에서 먼저 그 밸류체인의 모든 행을 null과 `model_version = 'rule-propagation-v1'`로 되돌린 뒤, 예측한 행을 배치로 갱신하고 `model_version = 'rule-propagation-v1|impact-hgb-v1'`로 바꾼다. 두 번 돌려도 결과가 같다.

## 6. 화면

### 6.1 백엔드

- `EventNodeResponse`에 `impactMagnitude`를 추가한다(`impactDirection` 다음). `EventQueryRepository`의 노드 조회에 `i.impact_magnitude`를 넣고 `EventService`가 넘긴다.
- `docs/api-specification.md`의 events 절에 `impactDirection`, `impactMagnitude`, `confidence` 설명을 적는다.
- 통합 테스트: 세 값을 가진 행과 null인 행을 시드하고 응답에 그대로 나오는지 확인한다.

### 6.2 프론트

- `EventNode` 타입에 `impactMagnitude: number | null`을 추가한다.
- 노드 모양 결정을 순수 함수 `nodeStyle(node)`(새 파일 `FrontEnd/src/features/event/nodeStyle.ts`)로 뺀다. 결과는 채움색, 테두리색, 속 빈 원 여부, 반지름이다.

  | 노드 상태 | 채움 | 반지름 |
  |---|---|---|
  | 모델 미적용(`confidence`가 null, OK) | 지금 색(근거 `--primary`, 추정 `--accent`) | 지금 규칙(근거 10 + 8 × 점수, 추정 8 + 10 × 점수) |
  | 관계 판단 보류(HOLD) | 지금 회색(`--text-4`, 불투명도 0.6) | 지금 규칙 |
  | 상승 / 하락 / 중립 | `--pos` / `--neg` / 새 토큰 `--impact-neutral` | 9 + 12 × 세기 |
  | 방향 보류(`confidence`는 있고 방향이 null) | 속이 빈 원. 테두리는 근거·추정 색 | 9 + 12 × 세기 |

- `--impact-neutral`은 `events.css`에 정의하고 판단 보류 회색과 구분되는 밝기로 둔다. 다크 모드 값도 함께 둔다.
- 선택 표시는 노드 바깥에 별도 원(반지름 + 4)으로 그려 속 빈 원의 테두리와 겹치지 않게 한다.
- 선 모양(근거 실선, 추정 점선)은 그대로 둔다.
- 범례 추가 항목: 상승, 하락, 중립, 속 빈 원(방향 보류), "색 없는 노드: 영향 모델 미적용(해외 상장·판단 보류)".
- 노드의 `title`과 `aria-label` 끝에 "상승 추정", "하락 추정", "중립 추정", "방향 보류" 중 하나를 붙인다.
- 근거 패널(모델이 돈 노드만):
  - 방향이 있으면 "모델 추정: 상승 · 신뢰도 62% · 세기 0.31"
  - 방향이 없으면 "영향 방향 보류 · 신뢰도 41%"
  - 그 아래 항상 "과거 비슷한 기사에 시장이 어떻게 반응했는지로 학습한 추정치이며, 주가 예측이 아닙니다."

## 7. 검증 보고서 (`docs/nexus/impact-model-report.md`)

`train-impact`가 매번 새로 쓴다. 담는 내용:

1. 실행 일시, 데이터 기간, 모델 버전, 감성 모델 리비전, τ와 선택 결과(통과 또는 기준 미달)
2. 학습·검증·시험 표본 수와 정답 분포(가중치 반영)
3. 시험 구간 비교표: 항상 중립, 규칙, 감성만, 전체 모델 × 정확도, macro-F1(세 클래스 F1의 단순 평균), log-loss(항상 중립과 규칙은 확률이 없으므로 "-")
4. 나눠 보기: 근거·추정별, 첫 관계 종류별 정확도와 macro-F1
5. τ에서의 커버리지(방향을 낸 비율)와 그 표본의 정확도
6. 보정표: 신뢰도 구간(0.1 단위)별 표본 수, 평균 신뢰도, 실제 정확도
7. 중요한 입력: 시험 구간에서 특징 하나씩 섞었을 때 log-loss가 늘어난 정도(permutation importance) 상위 10개
8. 한계: §9의 항목

## 8. 테스트

| 대상 | 내용 |
|---|---|
| `labels.py` | 손으로 계산한 주가로 AR_d, σ, z, 경계값(±0.5), 60일 중 50일 미만이면 정답 없음 |
| `features.py` | 경로 부호(경쟁 1번 → −1, 동시언급 포함 → 0), 언급 위치, 장 마감 후 판정, 급증 배율이 출고 시각 이후 기사를 세지 않음, 직전 5일 수익률 |
| `model.py` | 합성 데이터(신호를 심은 데이터)에서 모델이 항상 중립보다 나음, τ 선택 규칙(통과·기준 미달·200건 미만), 신뢰도 < τ이면 방향 null, 세기 = \|p_상승 − p_하락\|, 표본 가중치 반영, 저장 후 불러온 모델의 예측이 같음 |
| `sentiment.py` | 가짜 모델로 배치 처리, 라벨 순서 매핑, 이미 점수 낸 기사 건너뛰기, 중간 저장 후 이어 돌리기 |
| DB 갱신 | 테스트 DB에서 두 번 돌려도 같은 결과, HOLD·나스닥 행은 null, 되돌리기 후 갱신 |
| `report.py` | 가짜 평가 결과로 보고서의 표와 "기준 미달" 문구 |
| 백엔드 | `impactMagnitude`가 응답에 포함되고 null도 그대로 나옴 |
| 프론트 | `nodeStyle`을 `node --test`로 상태 4가지 검사. 브라우저에서 데스크톱·모바일 폭으로 확인 |

실제 데이터 실행 예상 시간: 감성 분석 CPU 약 1시간, 학습 몇 분, 예측과 DB 반영 약 10분.

## 9. 리스크와 한계

| 항목 | 대응 |
|---|---|
| 모델이 기준선보다 크게 낫지 않을 수 있다 | 숫자를 그대로 공개한다. τ를 높여 확신 있는 것만 방향을 내고 나머지는 속 빈 원으로 둔다. "모르면 모른다고 표시하는 것"을 기능으로 설명한다 |
| 설치·다운로드가 필요하다 | PyTorch CPU(약 200MB), transformers, KR-FinBERT 가중치(약 400MB, Hugging Face 공식). 실제로 받기 전에 사용자 승인을 받는다 |
| 관계 그래프에 미래 정보가 섞여 있다(slice1-run §3.4) | 보고서와 발표 자료에 한계로 적는다. 전파 점수·간선 출처 특징이 시험 성적을 부풀릴 수 있다 |
| 학습 구간 이벤트의 표시값은 학습에 쓰인 사례다 | 지도에 보이는 2025년 이벤트의 결과는 시험 성적보다 좋아 보일 수 있다. 데모 시나리오는 시험 구간(2026-07 이후) 이벤트에서 고른다 |
| 같은 날 기사가 여러 건 겹친다 | 어느 기사 때문에 주가가 움직였는지 구분할 수 없다. 표본 가중치로 영향만 줄이고 보고서에 적는다 |
| 기사 감성은 기업별이 아니다 | 기사 전체의 감성이라 특정 기업에 대한 논조와 다를 수 있다. 관계 판별기를 만들 때 기업 구간 감성으로 바꿀 수 있다 |
| 일별 주가에는 잡음이 많다 | 중립 구간(±0.5σ)을 두고, 지표는 macro-F1과 보정표로 함께 본다 |
