# NEXUS 설계: 빅카인즈 은하 발행과 국내 상장사 범위

- 작성일: 2026-10-18
- 배경: 로컬 DB에는 은하가 읽는 발행 스냅샷과 관계 점수가 없어서 메인 화면(`/`, 3D 은하)이 비어 있다(`GET /api/graphs/latest` → 404 `GRAPH_SNAPSHOT_NOT_FOUND`). 레포의 `AI/graph/data/db_full_20260922`는 COSMOS가 2026-09-22에 크롤링 뉴스·DART로 만든 옛 그래프라 쓰지 않는다. 서비스는 빅카인즈 데이터를 중심으로 만든다.
- 앞선 문서: [전체 설계](2026-10-13-nexus-bigkinds-design.md), [영향 모델](2026-10-16-nexus-impact-model-design.md)

## 1. 목표와 성공 기준

**목표.** 빅카인즈 기사에서 나온 관계만으로 은하 그래프를 만들어 발행하고, 서비스 전체(은하·이벤트 지도·영향 모델)를 국내 상장사로 맞춘다.

**성공 기준.**

1. `nexus publish-graph`를 실행하면 은하에 국내 반도체 기업이 행성으로, 빅카인즈 관계가 간선으로 보인다. 30일·1년·전체 기간 탭이 모두 동작한다.
2. 간선을 누르면 그 관계가 나온 빅카인즈 기사 목록이 근거 패널에 나온다.
3. 은하와 이벤트 지도 어디에도 나스닥 기업이 나오지 않는다.
4. 같은 명령을 두 번 돌려도 결과가 같고, `load`를 다시 돌려도 오류가 나지 않는다.
5. 기존 테스트(파이썬 127개, 백엔드 212개, 프론트 18개)와 새 테스트가 모두 통과한다.

## 2. 결정 사항

| 항목 | 결정 | 근거 |
|---|---|---|
| 간선 출처 | 빅카인즈만. COSMOS 옛 관계(약 93개)는 은하에 넣지 않는다 | 사용자 결정(2026-10-18) |
| 기업 범위 | 국내 상장사(KOSPI·코스닥)만. 은하와 이벤트 지도 모두 | 사용자 결정(2026-10-18) |
| 순서 | 반도체로 은하 발행을 먼저 끝내고, 그다음 2차전지·자동차로 확장 | 사용자 결정. 발행 단계는 처음부터 여러 밸류체인을 묶을 수 있게 만든다 |
| 은하 코드 | 기존 은하 화면과 API를 그대로 쓰고, 필요한 곳만 고친다 | 은하는 발행 스냅샷과 점수 테이블만 읽는다 |
| 스키마 | V11 마이그레이션 하나. V10은 수정 금지 | 관계 출처 CHECK에 값 하나만 추가하면 된다 |

## 3. 국내 상장사로 범위 축소

- 기업 사전을 만들 때 KOSPI·코스닥만 남긴다. `CHAINS` 설정에 `markets = ("KOSPI", "KOSDAQ")`를 두고 `build-master`가 그 밖의 시장을 버린다.
- 시드 파일(`semis_seed.csv`)의 나스닥 12개 행은 지우지 않는다. 나중에 다시 넣을 수 있게 남겨 두고, 사전 생성 단계에서만 거른다.
- 사전이 바뀌므로 아래를 다시 돌린다. 감성 점수는 기사 단위 캐시라 다시 계산하지 않는다.

  | 단계 | 바뀌는 것 | 예상 시간 |
  |---|---|---|
  | `build-master` | 기업 61개 (KOSPI 14, 코스닥 47) | 몇 초 |
  | `analyze` | 나스닥만 언급한 기사는 이벤트에서 빠지고, 나스닥을 거치는 추정 경로가 사라진다. 기업쌍 상위 300개가 바뀌어 새 쌍은 빅카인즈 API를 추가로 부른다 | 약 20~30분 |
  | `load` | 사라진 이벤트는 정리된다(`prune_events`) | 약 10분 |
  | `train-impact`, `predict-impact` | 특징(언급 기업 수, 경로)이 바뀌어 다시 학습·예측한다 | 약 2분 |
  | `publish-graph` | 새 명령 (§5) | 몇 분 |

- 바뀐 결과(이벤트 수, 이벤트당 추정 수, 영향 모델 지표)는 `docs/nexus/slice1-run.md`에 새 절로 기록한다.
- DB의 `company` 테이블에 이미 들어간 나스닥 기업 행은 지우지 않는다. 은하는 시장으로 거르고, 이벤트는 다시 적재하면서 나스닥 행이 빠진다.

## 4. 은하에 보이는 것

**행성.** NEXUS 기업 사전의 국내 기업 전체(반도체 61개). 업종 자리에는 "반도체 장비"처럼 밸류체인 + 역할을 넣어 은하의 나선 팔이 역할별로 묶이게 한다.

**간선 두 종류.**

| 종류 | 출처 | 모양 |
|---|---|---|
| 근거 관계 (공급·협력·경쟁) | 빅카인즈 기사 구간(hilight)에서 규칙으로 뽑은 관계 | 기존 은하 색·굵기 그대로 |
| 함께 언급 (`CO_MENTIONED`) | 빅카인즈 개체명에서 같은 문장에 함께 나온 기업쌍 | 회색, 흐리게, 흐름 애니메이션 없음 |

- 같은 기업쌍에 둘 다 있으면 근거 관계를 남긴다.
- 함께 언급은 기간마다 기업당 상위 5개(동시언급 기사 수 기준)만 남긴다.
- 은하 아래 관계 종류 토글에 "함께 언급"을 추가한다(기본 켜짐).

**기간 탭.** 30일, 1년, 전체. 은하의 10년 탭(`10Y`)에는 수집한 전체 기간(지금은 22개월)을 넣는다.

**근거 패널.** 그 관계가 나온 빅카인즈 기사 목록(제목·언론사·날짜·원문 링크). 근거 관계는 hilight 문장도 함께 보여준다.

## 5. 발행 명령 `nexus publish-graph --database-url URL`

- `load` 다음에 돌린다. 분석이 끝난 모든 밸류체인(`nexus/data/analyzed/<chain>/relations.pkl`이 있는 것)을 스냅샷 하나로 묶는다. 은하 점수 테이블은 매번 전체를 갈아 끼우므로 밸류체인별로 따로 발행하지 않는다.
- 기준 시각 `as_of` = (모든 밸류체인 수집 기사의 마지막 출고일 + 1일) 00:00 KST. 기간은 `[as_of − 30일, as_of)`(30D), `[as_of − 365일, as_of)`(1Y), 전체(10Y).
- 한쪽이라도 국내 상장사가 아닌 기업이 걸린 간선은 만들지 않는다. 기업 화면(`/graphs/companies/{id}`)의 주변 탐색은 시장을 거르지 않기 때문이다.

### 5.1 간선과 점수

| 간선 | 기간에 넣는 조건 | 점수(0~100) | 연결하는 근거 기사 |
|---|---|---|---|
| 근거 관계 | 근거 조각 중 기사 날짜가 기간 안인 것이 1개 이상 | 60 + 10 × min(기간 안 조각 수, 4) | 기간 안 근거 조각의 기사, 문장 포함 |
| 함께 언급 | 기간 안 기사로 다시 센 동시언급이 3건 이상이고 NPMI > 0. 기업당 상위 5개의 합집합 | 60 × log(1+n) / log(1+그 기간 최대 n) | 두 기업이 같은 문장에 나온 기간 안 최근 기사 최대 20건 |

- 동시언급은 기존 `sentence_comentions`를 기간별 기사 묶음에 그대로 적용한다.
- 점수는 `news_score`와 `score`에 같은 값을 넣고 `disclosure_score`는 비운다. 은하 프론트는 `news_score`만 있어도 간선을 그린다.
- `confidence`: 근거 관계는 기간 안 조각 신뢰도의 최대값, 함께 언급은 NULL. `impact_direction`은 NULL.
- `evidence_count`는 실제로 넣은 근거 기사 행 수와 같아야 한다. 0보다 큰데 근거 API가 비어 있으면 은하 툴팁이 로딩 상태로 남는다.

### 5.2 DB 반영 (한 트랜잭션, 매번 전체 교체)

1. **V11 마이그레이션:** `company_relationship.relation_source` CHECK에 `COMENTION`을 추가한다. `load_relations`는 다시 돌 때 `relation_source = 'NEWS'` 관계를 정리하는데, 함께 언급이 같은 출처면 같이 지워지기 때문이다.
2. **관계 유형:** `CO_MENTIONED`(이름 "함께 언급", `UNDIRECTED`)를 없으면 추가한다.
3. **업종:** 밸류체인 역할별 업종("반도체 설계" … "반도체 고객")을 없으면 만들고, 기업마다 주 업종(`is_primary = true`)으로 연결한다. 이미 다른 주 업종이 있으면 바꾸지 않는다.
4. **관계 행:** 함께 언급 관계를 `relation_source = 'COMENTION'`으로 넣는다. 무방향 관계는 기업 키(`market:ticker`) 순으로 한 방향만 쓰고, 반대 방향 행이 이미 있으면 그 행을 쓴다.
5. **스냅샷:** `graph_snapshot`에 `status = 'PUBLISHED'`, `as_of_at = as_of`, `formula_version = 'nexus-bigkinds-v1'`, `model_version = 'nexus-slice-v1'`, `hdfs_uri = 'bigkinds://nexus/<as_of 날짜>'`, `published_at = now()`로 넣는다. 같은 `(as_of_at, formula_version)`이 있으면 그 행을 다시 쓴다. 나머지 `PUBLISHED` 스냅샷은 `SUPERSEDED`로 바꾼다. 같은 시각의 발행 스냅샷이 둘이면 은하가 빈 쪽을 고를 수 있다.
6. **점수:** `relationship_score_current`를 전부 지우고 새 행을 넣는다(빅카인즈만이라 다른 출처 점수는 없다).
7. **근거 기사:**
   - 이 명령이 넣은 행(`relationship_evidence.model_version = 'nexus-graph-v1'`)만 지우고 다시 넣는다.
   - 근거 조각 기사가 `source_document`에 없으면 뉴스 문서로 추가한다. 문서 ID는 `load`와 같은 규칙(`uuid5(NAMESPACE_URL, "bigkinds:document:" + news_id)`)이라 나중에 이벤트로 적재돼도 같은 행이 된다.
   - hilight 문장은 `document_evidence`에 넣는다. 그 부모인 `company_document` 행은 `model_version = 'nexus-graph-v1'`, `is_service_visible = false`로 이 명령이 소유한다. `load`는 `nexus-slice-v1` 행만 지우므로 외래키 오류가 나지 않는다.
   - 함께 언급의 근거 기사는 이미 적재된 이벤트 문서이므로 `evidence_id` 없이 문서만 연결한다.

## 6. 백엔드와 은하 화면 수정

| 위치 | 수정 |
|---|---|
| `GraphService` | 지원 universe에 `KOSDAQ` 추가. 기본값을 `KOSPI100,KOSDAQ`로 바꿔 은하가 KOSPI·코스닥을 보여준다(나스닥 제외). 명시적으로 `NASDAQ100`을 주면 지금처럼 동작한다 |
| `lib/meta.ts` | `CO_MENTIONED`: 라벨 "함께 언급", 회색, 무방향, 설명 "같은 문장에 함께 나온 기사 수 기반 · 관계의 근거는 아님" |
| `store/galaxy.ts`, `ControlDock.tsx` | 기본 활성 유형에 `CO_MENTIONED` 추가, 토글 버튼 추가 |
| `lib/graph.ts` | 기업쌍마다 간선 하나만 남길 때 근거 관계를 함께 언급보다 우선한다(점수와 관계없이) |
| `RelationLines.tsx` | `CO_MENTIONED`는 투명도를 낮추고 흐름 애니메이션을 끈다 |

이벤트 지도 화면과 이벤트 API는 고치지 않는다. 나스닥 제외는 데이터(§3)로 처리된다.

## 7. 테스트

| 대상 | 내용 |
|---|---|
| 기업 사전 | `markets` 밖의 시드(나스닥)가 사전에서 빠진다 |
| 발행 계산 | 기간별 동시언급 재계산, 기업당 5개 제한, 국내 상장사가 아닌 간선 제외, 점수 범위(함께 언급 ≤ 60 ≤ 근거 관계), 근거 기사 수 = 연결 행 수, 기준 시각과 기간 경계 |
| 발행 DB 반영 | 스냅샷 재사용과 `SUPERSEDED` 처리, 두 번 돌려도 같은 결과, 발행 뒤 `load`를 다시 돌려도 외래키 오류 없음, 업종 연결, 무방향 관계 방향 하나 |
| 백엔드 | 기본 universe에 코스닥 기업이 포함되고 나스닥 기업은 빠진다 |
| 프론트 | 같은 쌍에서 근거 관계가 남는다(순수 함수), `CO_MENTIONED` 메타 |
| 실제 확인 | §3 재실행 후 발행, 은하에서 행성·간선·기간 탭·근거 패널 확인, 이벤트 지도에 나스닥 없음 |

## 8. 리스크와 한계

| 항목 | 대응 |
|---|---|
| 근거 관계가 적다(지금 약 23개) | 은하 대부분이 회색 함께 언급 선이 된다. 범례와 설명에 "관계의 근거는 아님"을 분명히 쓰고, KPF-BERT 관계 판별기로 근거 관계를 늘리는 것을 다음 과제로 둔다 |
| 나스닥 제외로 해외발 전이가 사라진다 | "엔비디아 실적 → 국내 공급사" 같은 경로는 이벤트 지도에서 보이지 않는다. 사용자 결정으로 받아들인다 |
| 데이터가 수집 마지막 날 기준이다 | 실시간 수집을 붙이기 전까지 갱신되지 않는다. 은하의 "새 스냅샷 가능" 표시는 기준 시각 1시간 뒤부터 계속 켜진다 |
| 재분석 때 빅카인즈 API 추가 호출 | 새 기업쌍 검색만 호출하고 나머지는 캐시를 쓴다. 키는 지금처럼 `.env`에서 읽는다 |
| 업종 이름이 은하 색 표에 없다 | 이름 해시로 색이 정해진다. 필요하면 색 표에 추가한다 |
