# NEXUS 설계: KPF-BERT 관계 판별기

- 작성일: 2026-10-18
- 배경: 관계 단어 검색으로 받아 둔 빅카인즈 hilight 중 두 회사 이름이 한 문장에 함께 나오는 문장이 10,332개(967쌍) 있다. 지금 규칙(COSMOS)은 이 중 85개만 근거로 인정해 근거 관계가 37개에 그친다([slice1-run §8](../../nexus/slice1-run.md)). 규칙은 짧은 hilight에서 표현을 많이 놓치고, 느슨한 패턴은 나열 문장을 잘못 읽는다.
- 앞선 문서: [전체 설계](2026-10-13-nexus-bigkinds-design.md)(③ 근거 관계: 규칙 → KPF-BERT 관계 판별기), [빅카인즈 은하](2026-10-18-nexus-bigkinds-galaxy-design.md)

## 1. 목표와 성공 기준

**목표.** 10,332개 문장을 KPF-BERT로 판별해, 지금 정확도(약 85%)를 유지하면서 근거 관계를 늘린다.

**성공 기준.**

1. 시험 데이터에서 관계로 인정한 판별의 정확도(precision)가 0.85 이상이다.
2. 근거 관계 수가 지금(37개)보다 늘고, 그 수와 시험 성적이 검증 보고서에 나온다.
3. 판별 결과가 기존 흐름(analyze → load → publish-graph)으로 이벤트 지도와 은하에 반영된다.
4. 모델 파일이 없으면 지금처럼 규칙만으로 돈다. 기존 테스트와 새 테스트가 모두 통과한다.

## 2. 결정 사항

| 항목 | 결정 | 근거 |
|---|---|---|
| 라벨링 | Claude가 약 2,000문장에 정답을 붙이고, 사람이 무작위 100개를 검토한다 | 사용자 결정(A안). 기획서 원칙 "LLM은 학습용 라벨링에만"과 일치. 서비스에서 판별하는 것은 KPF-BERT |
| 기본 모델 | `jinmang2/kpfbert`, 리비전 `dc732cc2aaa998959a2721e06ed10f98f2c51a0f`, `model.safetensors`(454MB) | 공식 KPF-BERT 가중치를 옮긴 공개 저장소 중 가장 많이 쓰인다. 리비전 고정 |
| 실행 장치 | CPU | AMD 그래픽카드라 CUDA가 없다. 학습 30분 안팎, 판별 10분 안팎 |
| 정답 기준 | 두 회사의 관계를 문장이 직접 말할 때만 관계. 제3자와 각각 관계가 있다는 나열 문장은 "관계 없음" | 2026-10-18 정확도 점검에서 정한 기준 |
| 데이터 보관 | 문장·라벨·모델은 `nexus/data/relations/`(git 제외). 레포에는 코드와 보고서(숫자)만 | 뉴스 문장 원문을 공개 레포에 올리지 않는다 |
| 스키마 | 바꾸지 않는다 | 판별 결과는 기존 근거 조각(`EvidenceSnippet`)으로 들어간다 |

## 3. 문장 모으기

- 기존 analyze와 같은 검색(상위 300 문장 동시언급 쌍의 기본 검색 + 1,333쌍 관계 단어 검색)을 **캐시에서만** 읽는다. 캐시에 없는 요청은 부르지 않고 건너뛴다.
- hilight를 기존 `hilight_fragments`로 문장 단위로 나누고, 두 회사 이름이 모두 "단독 이름"(`_standalone` 규칙)으로 나오는 문장만 남긴다.
- 같은 (문장, 기업쌍)은 하나로 친다. 문장마다 `fragment_id` = sha1(문장 + 두 기업 키)의 앞 16자.
- 결과: `nexus/data/relations/fragments.parquet` (fragment_id, 기업 A 키, 기업 B 키, A 별칭, B 별칭, 문장, news_id, 제목, 언론사, 출고 시각, 링크, 규칙 판정(관계·패턴 또는 없음)). A·B는 기업 키 사전순이다.

## 4. 라벨링

- **표본 약 2,000개:** 규칙이 관계로 본 문장은 느슨한 패턴까지 전부 넣는다(약 400). 나머지는 무작위로 채우되 한 기업쌍이 20개를 넘지 않게 한다. 삼성전자–SK하이닉스 같은 쌍이 표본을 덮지 않게 하려는 것이다.
- **정답 7가지(A·B 기준):** `SUPPLY_AB`(A가 B에 공급), `SUPPLY_BA`, `INVEST_AB`(A가 B의 지분 보유·인수·자회사로 둠), `INVEST_BA`, `PARTNER`, `COMPETE`, `NONE`.
- **라벨러:** Claude 하위 에이전트가 100문장씩 나눠 붙인다. 지시문에는 정답 기준과 예시(맞는 예, 나열 문장 같은 틀린 예)를 넣고, 결과는 JSON(fragment_id, label)으로 받는다. 형식이 맞지 않거나 빠진 문장은 다시 요청한다.
- **사람 검토:** 무작위 100개를 `review.csv`(문장, 라벨, 검토 칸)로 내보낸다. 사용자가 맞고 틀림을 표시하면 일치율을 보고서에 적는다. 검토가 늦어지면 학습은 먼저 진행하고, 보고서에 "사람 검토 대기"로 표시한다.
- 결과: `nexus/data/relations/labels.jsonl`.

## 5. 학습

- **입력:** 문장에서 두 회사 이름을 표시한다. A는 `@ 이름 @`, B는 `# 이름 #`로 감싼다(entity marker 방식). 최대 길이 128 토큰.
- **데이터 늘리기:** 학습 데이터는 A·B 표시를 맞바꾼 문장도 넣는다(방향 라벨은 뒤집는다).
- **분할:** 기업쌍 단위로 학습 70% · 검증 15% · 시험 15%. 같은 기업쌍이 두 구간에 들어가지 않는다.
- **설정:** `AutoModelForSequenceClassification`(7클래스), 학습률 2e-5, 배치 16, 4에폭, 클래스 가중치(빈도 역수), `random_state` 0. CPU 8스레드.
- **확신 기준 τ:** 검증 구간에서 관계로 인정한 판별(NONE이 아니고 최대 확률 ≥ τ)의 정확도가 0.85 이상이 되는 가장 작은 τ(0.50~0.95, 0.05 간격). 없으면 0.95.
- 결과: `nexus/data/relations/model/`(가중치·토크나이저·τ·라벨 목록) + `docs/nexus/relation-model-report.md`.

## 6. 적용

- `analyze`가 모델 폴더를 찾으면 그 기업쌍 문장을 모두 판별하고, NONE이 아니면서 확률이 τ 이상인 문장을 근거 조각으로 만든다(`pattern = "kpfbert"`, `confidence` = 확률, 방향은 라벨대로).
- 규칙 근거 조각과 합친다. 같은 (기사, 문장, 관계)는 한 번만 센다. 관계 확정은 지금처럼 신뢰도 noisy-OR ≥ 0.5다.
- 모델 폴더가 없거나 torch가 없으면 규칙만 쓴다.

## 7. 명령

| 명령 | 하는 일 |
|---|---|
| `nexus relation-fragments --chain semis` | §3 문장 모으기 → `fragments.parquet`, 라벨링 표본 → `sample.jsonl` |
| (Claude 라벨링) | `sample.jsonl` → `labels.jsonl`, 검토용 `review.csv` |
| `nexus train-relations --chain semis` | §5 학습 → 모델 폴더와 검증 보고서 |
| `nexus analyze --chain semis` 이후 기존 흐름 | §6 판별이 근거 조각에 더해진다 |

## 8. 검증 보고서 (`docs/nexus/relation-model-report.md`)

- 라벨 분포, 사람 검토 일치율(또는 "검토 대기")
- 시험 구간: 클래스별·전체 정확도와 재현율, 혼동 행렬, 같은 시험 문장에서 규칙의 정확도·재현율
- τ와 그때 인정 비율
- 판별 적용 후 근거 관계 수(종류별)와 근거 관계가 있는 기업 수, 전후 비교
- 한계: LLM 라벨의 잡음, 표본 크기, hilight가 200자로 잘려 문맥이 짧음

## 9. 테스트

| 대상 | 내용 |
|---|---|
| 문장 모으기 | 캐시에 없는 요청은 부르지 않음, 단독 이름 규칙, (문장, 쌍) 중복 제거, fragment_id 고정 |
| 표본 | 규칙 판정 문장 전부 포함, 쌍당 20개 상한, 크기 |
| 입력 | 이름 표시, A·B 맞바꾸기와 방향 라벨 뒤집기 |
| 분할 | 기업쌍이 두 구간에 걸치지 않음 |
| τ | 정확도 0.85를 넘는 가장 작은 값, 없으면 0.95 |
| 적용 | 가짜 판별기로 근거 조각 생성(방향·확률·pattern), 규칙과 중복 제거, 모델 없으면 규칙만 |
| 실제 실행 | 라벨링, 학습, 보고서, analyze → load → publish-graph, 관계 수 확인 |

## 10. 리스크

| 항목 | 대응 |
|---|---|
| LLM 라벨이 틀릴 수 있다 | 정답 기준과 예시를 지시문에 넣고, 사람 검토 일치율을 보고서에 공개한다 |
| 정확도 0.85를 못 넘을 수 있다 | τ를 0.95까지 올리고, 그래도 안 되면 모델을 쓰지 않고 규칙만 유지한다(보고서에 기록) |
| CPU 학습 시간 | 표본 2,000개·4에폭 기준 30분 안팎. 넘치면 에폭을 줄인다 |
| 모델 라이선스 | KPF-BERT는 한국언론진흥재단 모델이다. 해커톤 주최가 재단이라 사용 목적에 맞다. 보고서에 출처와 리비전을 적는다 |
