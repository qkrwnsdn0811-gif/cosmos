# GALAXY — 뉴스 × 주가 상관관계 3D 탐사 프로토타입

> 인터스텔라식 차원 이동으로 기업 간 관계를 탐색하는 프론트엔드 프로토타입.
> React 19 + Vite + Three.js / React Three Fiber.

```bash
npm install
npm run dev      # (= npm run vite / npm start, http://localhost:5173)
npm run build
```

---

## 1. 이 프로토타입이 증명하려는 것

기획 피드백에서 나온 요구를 **화면으로 확인 가능한 형태**로 옮겼다.

| 피드백 | 프로토타입에서의 대응 |
| --- | --- |
| 상관관계를 어떤 기준으로 판단할지가 핵심 | `60영업일 롤링 상관계수`를 화면에 명시하고, 임계값을 사용자가 직접 조절 |
| 관계 판단 근거 + **근거가 바뀐 이유**를 보여줘야 신뢰를 얻는다 | 관계 클릭 → `근거 변경 이력` (상관계수 급변 시점 + 그 시점의 뉴스/거시 이벤트) |
| 뉴스만이 아니라 과거 주가·기업 간 동반 움직임을 함께 봐야 한다 | 상관계수는 **뉴스가 아니라 수익률 시계열에서 계산**하고, 뉴스는 그 위에 마커로 얹는다 |
| 실적 외에 전쟁·거시 요인도 고려해야 한다 | 타임라인에 거시 이벤트(금리/지정학/통상/AI CAPEX) 별도 표기, 현재 시점에 작동 중인 거시 이벤트를 상단에 노출 |
| 경쟁사처럼 보여도 공생 관계일 수 있다 | 관계 유형을 `공급망 / 고객사 / 경쟁·대체 / 거시 동조 / 그룹·지분 / 미분류`로 나누고 맥락 문장을 함께 제공 |
| 범위를 좁혀서 시작하라 | 국내 20종목, 2024.09 ~ 2026.07 (영업일 500일) |
| 관계도를 신경망 형태 3D UI로 | 섹터 = 성단, 기업 = 항성, 관계 = 흐르는 중력선 |
| **예상하지 못한 연관성 발견**이 차별점 | `예상 밖 연결` 배지 — 섹터가 다른데 상관이 높고 사전 정의된 관계가 없는 쌍을 자동 표기 |
| 발표에서 사용 데이터와 검증 결과를 함께 | 모든 수치(상관계수·뉴스 이후 5일 수익률·동반 급변 일수)가 시계열에서 계산된 값 |

## 2. 화면 구성

### 차원(뷰) 3단계

| 단계 | 내용 |
| --- | --- |
| **INTRO** | 타이틀. `탐사 시작` |
| **GALAXY** | 전체 관계도. 섹터별 성단, 기업 = 항성, 관계 = 흐르는 곡선 |
| **WARP** | 웜홀 터널 + 하이퍼스페이스 스트릭. 이 사이에 씬을 교체한다 (2.3초) |
| **SYSTEM** | 선택 기업의 차원. 중심 항성 + 궤도에 배치된 연결 기업 + 하단 주가 리본 |

### 조작

| 입력 | 동작 |
| --- | --- |
| 항성 클릭 / 좌측 종목 클릭 | 해당 기업 차원으로 **워프** |
| 드래그 · 휠 | 회전 · 확대 |
| 관계 항목 클릭 | 근거 변경 이력 펼치기 |
| SYSTEM에서 위성 호버 → `이 기업으로 워프` | 차원 간 연쇄 이동 |
| `Space` | 타임라인 재생/정지 |
| `←` `→` (`Shift` = 20일) | 시점 이동 |
| `Esc` | 은하로 복귀 |

### 읽는 법

- **간선 색** = 관계 유형, **분홍색** = 예상 밖 연결
- **간선 밝기** = |상관계수|
- **항성 주변 파동** = 그 시점 전후 12영업일 내 뉴스 (앰버 = 호재, 시안 = 악재)
- **SYSTEM 궤도 반경** = 상관계수가 높을수록 중심에 가깝다. 위/아래 = 상관 부호
- **주가 리본** = 현재 시점 이후 구간은 흐리게 (시간 여행 은유)

## 3. 아키텍처

```
src/
├─ data/universe.js      ★ 데이터 계약 경계 — 지금은 시뮬레이터, 나중에 API 클라이언트로 교체
├─ store/useGalaxy.js    ★ 상태 계약 경계 — 단계 전환 / 필터 / 시점
├─ three/
│  ├─ Scene.jsx          Canvas 루트 + Director(카메라·워프 타이밍) + 포스트프로세싱
│  ├─ Warp.jsx           웜홀 터널 셰이더 + 하이퍼스페이스 스트릭
│  ├─ Nebula.jsx         fbm 성운 스카이돔
│  ├─ Starfield.jsx      배경 별 (포인트 셰이더)
│  ├─ GalaxyView.jsx     은하 뷰 (노드 + 간선 조립)
│  ├─ SystemView.jsx     기업 차원 뷰
│  ├─ CompanyNode.jsx    항성 1개
│  ├─ RelationLines.jsx  간선 전체를 메시 1개로 (화면 기준 두께 + 흐르는 펄스)
│  ├─ PriceRibbon.jsx    3D 주가 면적 차트 + 뉴스 빛기둥 + 툴팁
│  ├─ LabelSprite.jsx    한글 라벨 (캔버스 텍스처 → 스프라이트)
│  ├─ textures.js        공유 텍스처 / 시드 난수
│  └─ useGraph.js        ★ 3D 뷰와 우측 패널이 공유하는 그래프 조회 훅
└─ ui/                   Hud / LeftPanel / DetailPanel / Timeline / Intro
```

### 성능상 선택

- 간선은 개별 오브젝트가 아니라 **인덱스 메시 1개**. 정점 셰이더에서 카메라를 향해 빌보드해
  화면 기준 두께를 만든다 (`gl.LINES`는 대부분의 플랫폼에서 1px 고정이라 우주 공간에서 안 보인다).
- 모든 쌍(190개)의 롤링 상관계수를 **누적합으로 O(1) 윈도우 계산**해 기동 시 1회 사전 계산.
  타임라인을 재생해도 재계산 비용이 없다.
- `Director`는 스토어를 구독하지 않고 `getState()`로 읽어 매 프레임 React 리렌더를 만들지 않는다.
- 한글 라벨은 troika `<Text>` 대신 캔버스 텍스처 스프라이트 (기본 폰트에 한글 글리프가 없다).

## 4. 데이터 계약 — 백엔드/분산처리 팀과의 경계

**`src/data/universe.js` 하나만 교체하면 실데이터로 전환된다.** 현재 이 파일은
팩터 모델(`r = β_m·market + β_s·sector + pair + ε + shock`)로 시계열을 만들고
거기서 상관계수를 계산하는 시뮬레이터다. 프론트의 나머지 코드는 아래 함수 시그니처만 안다.

| 프론트가 호출하는 함수 | 대응하는 API (제안) | 비고 |
| --- | --- | --- |
| `COMPANIES`, `SECTORS` | `GET /api/companies` | 종목 마스터 |
| `buildGraph(day, {threshold, types})` | `GET /api/graph?date&window=60&threshold` | **Spark에서 사전 계산 후 저장** 권장 |
| `neighborsOf(id, day, opts)` | `GET /api/companies/{id}/neighbors?date` | 그래프의 부분 조회 |
| `corrSeries(a, b)` | `GET /api/pairs/{a}/{b}/corr` | 롤링 상관계수 시계열 |
| `relationTimeline(a, b, {upTo})` | `GET /api/pairs/{a}/{b}/changepoints` | **change-point 검출 결과** + 원인 후보 |
| `inferContext(a, b, day)` | `GET /api/pairs/{a}/{b}/context?date` | 동반 급변 일수 + 창 내 공통 이벤트 |
| `newsFor(id, {from,to})`, `ALL_NEWS` | `GET /api/news?companyId&from&to` | 네이버 뉴스 API 수집 결과 + 감성 라벨 |
| `MACRO_EVENTS` | `GET /api/macro-events` | 거시 이벤트 |
| `normalizedPrice / priceAt / changePct` | `GET /api/prices?ids&from&to` | OHLCV |

### 분산처리 팀이 맡으면 좋은 것

1. **롤링 상관계수 전량 사전 계산** — 종목 N개면 쌍이 N²/2. 100대 기업이면 4,950쌍 × 영업일 수.
   Spark로 배치 계산 후 `(pair, date) → corr` 형태로 적재하면 프론트는 조회만 한다.
2. **change-point 검출** — 상관계수 시계열에서 급변 구간을 찾고, 그 창에 걸친 뉴스/거시 이벤트를
   원인 후보로 매칭. 이 결과가 곧 화면의 `근거 변경 이력`이다.
3. **뉴스 감성/이벤트 분류** — `tone(호재/악재)`, `tag(수주/규제/원자재/…)` 라벨링.
4. **이벤트 스터디** — 뉴스 발생 후 k일 초과수익률. 화면의 "발생 후 5영업일 %" 칸.

> 지금 프론트는 이 네 가지를 전부 **클라이언트에서 흉내내고 있다.** 실서비스로 가면 그대로 서버로 이관된다.

## 5. 프론트엔드 역할 분담 (3인 기준)

경계는 두 파일이다. **`store/useGalaxy.js`(상태 계약)와 `data/universe.js`(데이터 계약)를 먼저 고정**하면
아래 셋이 서로 파일을 건드리지 않고 병렬로 갈 수 있다.

### FE-A · 씬 & 연출 (Three.js 코어)

- 담당: `three/Scene.jsx`, `Warp.jsx`, `Nebula.jsx`, `Starfield.jsx`, `LabelSprite.jsx`
- 일: 카메라 디렉터(단계 전환·워프 타이밍), 셰이더, 포스트프로세싱, 프레임 예산 관리
- 산출물: `phase` 상태만 바꾸면 연출이 알아서 붙는 구조 유지
- 난이도가 가장 높고 디자인 임팩트를 결정한다. **셰이더 경험자에게 배정.**

### FE-B · 데이터 시각화 (그래프 & 차트)

- 담당: `three/GalaxyView.jsx`, `SystemView.jsx`, `CompanyNode.jsx`, `RelationLines.jsx`, `PriceRibbon.jsx`
- 일: 레이아웃 알고리즘(성단 배치·궤도 배치), 간선 표현, 하이라이트/디밍 규칙, 3D 주가 차트
- 확장 과제: 종목 수가 100개로 늘었을 때의 레이아웃(force-directed 또는 사전 계산 좌표)과
  인스턴싱 전환

### FE-C · 상태 · UI · 연동

- 담당: `store/`, `ui/*`, `data/universe.js` → API 클라이언트 전환
- 일: HUD/필터/타임라인/상세 패널, 키보드 인터랙션, 로딩·에러 상태, 반응형
- 확장 과제: React Query 도입, `universe.js`를 `api/` 레이어로 분리하고 목/실서버 스위치

### 협업 규칙 제안

- 3D 컴포넌트는 **스토어를 직접 읽되 스토어에 쓰지 않는다** (쓰기는 액션 함수로만).
- 매 프레임 도는 로직(`useFrame`)에서 `useGalaxy(s => ...)` 구독 금지 → `useGalaxy.getState()` 사용.
- 새 데이터가 필요하면 컴포넌트 안에서 계산하지 말고 **`universe.js`에 함수를 추가**한다.
  그래야 나중에 API로 갈아끼울 때 한 파일만 바뀐다.

## 6. 시연 시나리오 (발표용 3분)

1. **탐사 시작** — 은하 전체. "섹터가 성단, 기업이 항성, 선이 상관관계다."
2. 우측 `관계 랭킹` 상단 — 현대차↔기아(그룹·지분), 기아↔현대모비스(공급망), LG에너지솔루션↔삼성SDI(경쟁·대체).
   "상식적으로 알고 있는 관계가 데이터에서도 그대로 상위에 나온다." (= 모델이 상식을 재현한다)
3. 좌측 **`예상 밖 연결만 보기`** 체크 —
   반도체 ↔ 에너지·중공업 조합이 뜬다. "섹터는 다른데 왜 같이 움직이나?"
4. 그중 하나를 클릭 → **동반 급변 일수 / 공통 사건([AI] 엔비디아 실적 서프라이즈) /
   근거 변경 이력(상관계수 0.0 → 0.6)** 을 보여준다.
   "AI 데이터센터 CAPEX가 HBM 장비와 전력기기를 동시에 끌어올린 구간이다."
5. **타임라인 재생** — 시점이 흐르면서 관계도가 재구성된다.
   2025.11 이후 이 연결이 약해졌다가 2026 중반 다시 살아나는 것을 보여준다.
   "관계는 고정이 아니라 시점의 함수다."
6. 그 기업을 클릭 → **워프** → 기업 차원.
   주가 리본 위의 뉴스 빛기둥에 마우스를 올려 "이후 5영업일 수익률"을 보여주고 마무리.
